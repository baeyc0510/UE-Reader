# 언리얼 엔진 분석 어시스트 웹 앱 기획서

## 1. 목적

**언리얼 엔진을 편리하게 이해하자.**

언리얼 엔진 원본 소스와 Codex의 해설을 나란히 보여주는 로컬 웹 앱을 만든다. 사용자가 코드를 읽으며 구조, 실행 흐름, 클래스와 함수의 관계를 파악할 수 있도록 돕는다. 확인한 해설은 저장하고, 다음 분석에서 해당 코드와 함께 다시 불러온다.

왼쪽에는 원본 소스, 오른쪽에는 코드 구간에 연결된 해설을 표시한다. 가운데 링크 버튼을 켜면 양쪽 스크롤이 서로 대응하는 위치로 이동한다. 해설과 분석 기록은 앱 데이터로 저장하며 엔진 원본 파일은 수정하지 않는다.

제품은 엔진 분석을 지원하는 도구다. 문제 출제, 퀴즈, 복습, 학습 진도, 점수 기능은 제공하지 않는다.

## 2. 사용 경험의 원칙

- **코드를 보면서 설명을 읽는다.** 해설은 현재 파일의 코드 구간에 연결한다.
- **읽던 맥락을 유지한다.** 파일 이동 후에도 이전 위치, 해설, 질문 초안을 복원한다.
- **같은 설명을 다시 기다리지 않는다.** 저장된 해설을 먼저 불러오고 사용자가 요청할 때 생성하거나 갱신한다.
- **이동을 예측할 수 있다.** 링크 상태와 현재 대응 구간을 분명하게 표시한다.
- **질문 입력을 줄인다.** 파일과 라인은 선택으로 추가하고 직접 입력하지 않아도 되게 한다.
- **근거를 바로 확인한다.** 설명에서 원본 위치로 이동하고 이전 위치로 돌아올 수 있게 한다.
- **작업을 잃지 않는다.** 해설, 질문, 답변, 초안을 로컬에 저장한다.

## 3. 주요 분석 작업

| 작업 | 앱이 제공하는 지원 |
| --- | --- |
| 파일의 역할 파악 | 파일 개요, 주요 클래스·함수 목록, 관련 파일 링크 |
| 함수 구현 이해 | 역할, 입력과 결과, 처리 순서, 상태 변화, 분기 설명 |
| 엔진 구조 파악 | 코드에서 확인한 모듈·클래스 관계와 근거 위치 |
| 실행 흐름 추적 | 호출 위치와 관련 함수로 이동, 탐색 기록 복원 |
| C++ 및 엔진 문법 이해 | 선택한 매크로·타입·구문의 정의와 사용 맥락 설명 |
| 이전 분석 재사용 | 저장한 해설 검색, 코드 위치 복원, 후속 질문 |

관련 코드의 정의를 확인하지 못했거나 조사 범위가 일부에 그치면 그 범위를 답변에 표시한다. 검색 결과만으로 전체 호출 관계를 확인했다고 표현하지 않는다.

## 4. 화면 구성

```text
┌────────────────────────────────────────────────────────────────────┐
│ 소스 작업공간 · 빠른 검색 · 저장한 해설 · Codex 상태                  │
├──────────────┬───────────────────────┬───┬──────────────────────────┤
│ 파일 탐색기  │ 파일 탭 · 경로 · 이동 │링크│ 파일 개요 · 해설 목차    │
│ 접기 가능    ├───────────────────────┤버튼├──────────────────────────┤
│              │ 원본 소스             │   │ 코드 구간별 해설         │
│              │ C++ 하이라이트        │   │ 근거 파일과 라인         │
│              │ 라인 번호             │   │                          │
│              │                       │   ├──────────────────────────┤
│              │                       │   │ 질문 답변 · 컨텍스트     │
│              │                       │   │ 질문 입력                │
└──────────────┴───────────────────────┴───┴──────────────────────────┘
```

### 4.1 상단과 파일 탐색기

- 현재 소스 작업공간과 엔진 버전 정보를 표시한다. 버전을 확인하지 못하면 미확인으로 표시한다.
- 파일 탐색기는 접을 수 있고, 최근 파일과 즐겨찾기를 제공한다. 소스 폴더 지정 시 하위 폴더는 기본적으로 닫아 둔다.
- 빠른 검색에서 파일 이름, 상대 경로, 코드 문자열을 찾는다.
- 검색 결과에는 파일 경로, 라인, 주변 코드를 표시한다.
- 여러 파일을 탭으로 열고 탭마다 코드·해설 위치를 유지한다.
- `.cpp`, `.h`, `.inl` 등 분석에 필요한 소스 파일을 읽는다.

### 4.2 왼쪽 원본 소스

- 읽기 전용 소스에 C++ 문법 하이라이트와 라인 번호를 표시한다.
- 파일 내 검색, 지정 라인 이동, 선택 코드 복사를 지원한다.
- 라인 번호를 클릭하면 해당 라인을 질문 컨텍스트에 추가한다.
- Shift 클릭으로 라인 범위를 지정하고, 드래그한 코드도 컨텍스트로 추가할 수 있다.
- 컨텍스트에 추가된 코드와 해설이 대응하는 코드는 서로 구분해 표시한다.
- 파일 전환과 근거 링크 이동에 뒤로·앞으로 이동을 제공한다.

### 4.3 가운데 링크 버튼

- 소스와 해설 사이에 항상 보이는 ON/OFF 버튼을 둔다.
- 아이콘, 상태 텍스트, 툴팁으로 현재 상태를 표시한다. 색만으로 상태를 구분하지 않는다.
- 첫 사용에서는 ON으로 시작하며 이후에는 사용자의 마지막 설정을 유지한다.
- 두 주요 영역의 너비를 조절할 수 있게 하고, 링크 버튼의 조작 영역은 유지한다.

### 4.4 오른쪽 해설과 질문

- 위쪽에는 파일 개요와 접을 수 있는 해설 목차를 둔다.
- 본문은 함수·클래스·코드 블록 등 의미 있는 구간별 해설로 구성한다.
- 각 구간에는 제목, 대응 라인 범위, 설명, 관련 코드 링크를 표시한다.
- 긴 설명은 세부 내용을 접을 수 있게 하며 기본 설명의 길이도 조절할 수 있게 한다.
- 질문 입력창은 오른쪽 하단에 고정한다. 질문 컨텍스트는 파일명과 라인 범위로 표시하고 개별 제거를 지원한다.
- 질문 답변 영역은 접을 수 있게 한다. 질문 이력이 길어져도 코드에 대응하는 해설을 밀어내지 않게 한다.
- 답변에서 별도 코드 해설 생성을 요청할 수 있다. 현재 소스를 다시 분석해 구간별 해설을 만들고 원래 답변과 연결한다.

## 5. 양방향 스크롤 동기화

### 5.1 대응 기준

단순한 스크롤 비율이 아니라 **파일과 코드 범위에 연결된 해설 구간**을 기준으로 이동한다. 코드와 해설의 높이가 달라도 같은 내용을 볼 수 있어야 한다.

왼쪽에서 현재 읽는 구간은 화면 상단에서 약 1/3 지점의 라인을 기준으로 정한다. 오른쪽은 같은 기준선에 있는 해설을 기준으로 삼는다. 대응하는 코드와 해설에는 옅은 강조 표시를 적용한다.

### 5.2 링크 ON

- 왼쪽을 스크롤하면 오른쪽이 해당 코드의 해설로 이동한다.
- 오른쪽 해설 본문을 스크롤하면 왼쪽이 그 설명의 대표 코드 범위로 이동한다.
- 사용자가 직접 스크롤한 영역을 이동 기준으로 삼는다. 자동 이동이 반대쪽의 추가 이동을 유발하지 않게 한다.
- 한 해설이 여러 라인을 설명할 때는 같은 범위 안의 작은 스크롤마다 오른쪽을 반복 이동시키지 않는다.
- 대응 해설이 없는 코드에서는 관련 없는 해설로 이동하지 않는다. 해설 없음 상태와 해당 구간의 해설 생성 동작을 표시한다.
- 현재 파일의 해설에는 현재 파일의 대표 코드 범위를 지정한다. 다른 파일의 참고 링크는 사용자가 클릭할 때 연다.
- 질문 답변 이력의 스크롤은 동기화 대상에서 제외한다. 답변 속 근거 링크는 클릭으로 소스 위치를 연다.

### 5.3 링크 OFF와 재연결

OFF에서는 두 영역을 독립적으로 읽는다. 해설 목차나 근거 링크를 직접 선택하는 이동은 사용할 수 있다.

다시 ON으로 전환하면 마지막으로 사용자가 조작한 주요 영역을 기준으로 다른 영역을 맞춘다. 초기 기준이 없으면 왼쪽 소스 위치를 사용한다.

## 6. 해설 생성과 분석 질문

### 6.1 파일 해설

파일을 열면 저장된 해설을 먼저 불러온다. 해설이 없으면 빈 상태에서 `파일 개요 생성`과 `현재 코드 해설`을 제공한다. 스크롤만으로 새 Codex 요청을 보내지 않는다.

파일 개요는 역할, 주요 구성 요소, 관련 파일을 짧게 설명한다. 코드 해설은 선택한 범위나 현재 읽는 구간을 설명하고, 필요하면 주변 선언과 관련 정의를 함께 확인한다.

생성 중에도 사용자는 코드를 읽을 수 있다. 진행 상태, 부분 응답, 취소를 제공하고 완료된 해설을 읽기 방해 없이 추가한다. Codex 응답 때문에 왼쪽 위치나 작성 중인 질문이 바뀌지 않게 한다.

### 6.2 질문

파일을 열지 않아도 질문할 수 있다. 에이전트는 자체 지식과 웹 검색으로 조사 방향을 정하고, 지정된 소스 작업공간에서 파일 이름·코드를 검색해 필요한 파일을 직접 읽는다. 소스 폴더가 없으면 일반 지식과 웹 자료로 답한다.

에이전트가 선택한 실제 파일, 읽을 라인 범위와 선택 이유를 표시한다. 파일 없이 시작한 질문에서는 첫 추천 파일을 자동으로 연다. 사용자가 조사 중 파일을 열거나 질문을 수정했다면 자동 이동하지 않는다. 웹에서 참고한 자료는 출처 링크로 표시하고 로컬 소스 확인 결과와 구분한다.

사용자는 자유롭게 질문하거나 `역할 설명`, `호출 흐름`, `관련 구현 찾기`, `매크로 설명` 같은 분석 동작을 선택한다. 이 동작은 선택 코드에 대한 질문 입력을 돕는다.

질문에는 사용자가 코드 드래그 또는 라인 선택으로 명시한 범위만 첨부한다. 선택이 없으면 화면의 파일·코드를 자동 주입하지 않는다. 질문창에 첨부 여부를 표시하고 범위를 제거할 수 있게 한다. 선택한 코드가 있어도 답변 범위를 그 코드로 제한하지 않으며 에이전트는 질문에 필요한 관련 구현을 탐색한다.

후속 질문은 앞선 분석 맥락을 이어 사용한다. 사용자가 파일을 이동해도 기존 질문과 답변은 유지하며, 질문 컨텍스트에는 현재 대상이 분명하게 표시되게 한다.

### 6.3 답변 품질

- 설명은 지정된 소스에서 확인한 내용에 근거한다.
- 주요 주장에는 파일 경로와 라인 범위를 연결한다.
- 역할, 처리 순서, 상태 변화, 관련 코드를 질문에 필요한 만큼 설명한다.
- 실제 확인한 내용과 추론을 구분한다.
- 정의나 구현을 찾지 못한 부분은 확인하지 못했다고 표시한다.
- 복잡한 관계는 간단한 흐름도나 표로 표현할 수 있고, 근거 위치를 함께 제공한다.

## 7. 해설 저장과 다시 불러오기

### 7.1 저장 방식

해설과 분석 기록은 로컬 백엔드가 관리하는 앱 데이터 폴더에 저장한다. 저장 위치는 엔진 소스 폴더 밖에 두고 설정에서 확인할 수 있게 한다.

- 완료된 해설과 질문 답변은 자동 저장한다.
- 질문 초안, 열린 파일, 코드·해설 위치, 링크 상태도 저장한다.
- `저장` 동작으로 해설에 이름을 붙이거나 변경할 수 있다.
- 저장 상태를 `저장 중`, `저장됨`, `저장 실패`로 표시한다.
- 재생성한 해설은 이전 내용을 보존하며, 사용자가 사용할 버전을 선택할 수 있게 한다.
- 취소된 생성 결과는 부분 응답으로 구분하고, 완성된 해설처럼 기본 표시하지 않는다.

### 7.2 저장 항목

| 항목 | 용도 |
| --- | --- |
| 소스 작업공간 식별 정보와 상대 파일 경로 | 엔진별 해설 구분과 경로 복원 |
| 엔진 버전 정보, 파일 및 코드 구간의 내용 식별값 | 현재 소스와 저장 당시 소스 비교 |
| 해설 제목, 본문, 작성 시각, 생성 버전 | 해설 목록 표시와 이전 결과 선택 |
| 대표 코드 범위, 심볼 정보, 근거 위치 | 스크롤 동기화와 근거 이동 |
| 질문, 답변, 전달한 코드 컨텍스트 | 후속 분석과 근거 확인 |
| 탭, 스크롤, 링크 상태, 질문 초안 | 작업 재개 |

### 7.3 다시 불러오기

- `저장한 해설`에서 제목, 파일 경로, 해설 본문으로 검색한다.
- 현재 파일과 관련된 해설을 먼저 보여준다.
- 목록에 제목, 파일, 저장 시각, 소스 변경 여부를 표시한다.
- 항목을 열면 연결된 파일과 해설을 함께 불러오고 읽던 위치를 복원한다.
- 저장된 답변을 읽는 데 Codex 연결이나 재요청이 필요하지 않게 한다.
- 앱을 다시 열면 마지막 작업공간과 열린 탭을 복원한다.
- 소스 폴더가 이동했으면 새 폴더를 지정해 상대 경로를 다시 연결할 수 있게 한다.
- 삭제는 사용자의 명시적 동작으로 수행하며, 삭제 직후 취소할 수 있게 한다.

### 7.4 소스 변경 처리

저장한 해설이 다른 엔진 버전이나 변경된 코드에 그대로 연결되는 일을 막는다.

- 파일을 열 때 저장 당시와 현재 소스를 비교한다.
- 코드가 같으면 기존 해설과 연결 정보를 그대로 사용한다.
- 라인만 이동했고 대응 코드가 확실하면 위치를 갱신해 연결한다.
- 대응 위치가 불확실하거나 코드 내용이 바뀌었으면 변경 상태를 표시한다.
- 변경된 해설은 계속 읽을 수 있지만, 불확실한 위치를 스크롤 동기화 대상으로 사용하지 않는다.
- 사용자는 해당 구간만 다시 생성하거나 기준 위치를 직접 지정할 수 있다.
- 새 해설을 생성해도 기존 해설과 분석 기록을 자동 삭제하지 않는다.

## 8. 사용 시나리오

### 8.1 처음 파일 분석

소스 폴더 지정 → 빠른 검색으로 파일 열기 → 파일 개요 생성 → 필요한 코드 구간 해설 → 링크 ON으로 코드와 해설 함께 읽기 → 라인 선택 후 추가 질문 → 자동 저장.

### 8.2 관련 구현 추적

해설의 관련 코드 링크 선택 → 다른 파일 열기 → 구현 확인 및 질문 → 뒤로 이동 → 원래 코드와 해설의 읽던 위치 복원.

### 8.3 이전 분석 재개

앱 실행 → 마지막 작업 상태 복원 또는 저장한 해설 검색 → 연결된 소스와 해설 불러오기 → 필요하면 소스 변경 확인 → 후속 질문.

## 9. 반응 속도와 접근성

- 파일 탐색기를 접고 좌우 너비를 조절해 코드와 해설의 읽기 공간을 확보한다.
- 글자 크기, 밝은·어두운 테마, 줄바꿈을 설정하고 유지한다.
- 검색, 탭 이동, 뒤로 이동, 링크 전환, 질문 전송에 키보드 단축키를 제공한다.
- 큰 파일은 화면에 필요한 코드만 렌더링하고, 긴 해설과 기록도 필요한 항목부터 불러온다.
- 소스 색인은 진행 상태와 취소를 제공한다. 파일 목록이 준비되면 전체 색인 완료 전에도 파일을 열 수 있게 한다.
- 검색 요청, 파일 읽기, Codex 응답, 저장 상태를 구분해 보여준다.
- 오류는 화면 전체를 막지 않고 발생한 작업 영역에 표시하며 재시도를 제공한다.

## 11. 로컬 구성과 데이터 처리

구성은 `웹 UI ↔ 로컬 백엔드 ↔ 로컬 Codex`로 한다. 백엔드는 소스 읽기, 검색, 해설 저장, 코드 위치 연결, Codex 요청 관리를 담당한다.

Codex 연결은 로컬에 설치된 Codex 실행 환경을 사용한다. 구체적인 연결 인터페이스와 인증 방식은 구현 전에 확인한다.

- 사용자가 지정한 소스 폴더 안의 파일만 읽도록 경로를 검사한다.
- 엔진 원본은 읽기 전용으로 처리하고 Codex 요청도 분석 범위로 제한한다.
- 질문에 전달한 코드 범위와 추가로 참고한 파일을 확인할 수 있게 한다.
- 인증 정보가 필요하면 로컬 백엔드에서 관리한다.
- 해설과 분석 기록은 브라우저 임시 저장소에만 의존하지 않고 로컬 파일 또는 데이터베이스에 저장한다.
- 일반 로그에 원본 코드와 질문 내용을 불필요하게 남기지 않는다.

## 12. 구현 우선순위

### 12.1 첫 버전에 필요한 기능

- 소스 작업공간 지정, 파일 탐색, 탭, 파일·코드 검색
- C++ 하이라이트, 라인 번호, 읽기 전용 소스 보기
- 파일 개요와 코드 구간별 해설
- 가운데 링크 버튼과 양방향 스크롤 동기화
- 라인·범위 선택을 통한 질문 컨텍스트 추가
- 로컬 Codex 연결, 응답 표시, 취소, 재시도
- 해설과 질문 답변 자동 저장, 이름 지정, 검색, 다시 불러오기
- 이전 파일 위치와 마지막 작업 상태 복원
- 소스 변경 감지와 불확실한 위치의 동기화 제한
- 호출 흐름·라이프사이클·데이터 흐름 시각화, 단계별 해설과 검증된 코드 연결

### 12.2 이후 분석 편의 개선

- 심볼 정의와 참조 위치 탐색 정확도 개선
- 헤더와 구현 파일 간 빠른 이동
- 큰 구조도에서 하위 흐름을 펼치는 단계별 탐색
- 여러 파일에 걸친 분석 기록의 탐색과 정리

## 13. 완료 기준

1. 지정한 소스 폴더에서 파일을 찾아 열고, 원본을 수정하지 않은 상태로 읽을 수 있다.
2. 라인 번호 클릭과 범위 선택으로 파일·라인 정보를 질문에 추가하고 제거할 수 있다.
3. 현재 코드 구간의 설명과 근거가 오른쪽에 표시된다.
4. 링크 ON에서는 양쪽 스크롤이 대응 구간으로 이동하며 반복 이동이나 화면 흔들림이 없다.
5. 링크 OFF에서는 독립적으로 스크롤되고, 재연결 시 명시된 기준으로 위치가 맞춰진다.
6. 대응 해설이 없는 코드와 변경된 코드가 관련 없는 설명에 자동 연결되지 않는다.
7. 관련 코드로 이동한 뒤 이전 파일의 코드·해설 위치로 돌아올 수 있다.
8. 해설과 질문 답변을 저장하고, 앱 재시작 후 Codex 재요청 없이 불러올 수 있다.
9. 저장한 해설을 제목·파일·내용으로 찾고, 원본 코드와 함께 열 수 있다.
10. 소스 변경 또는 폴더 이동 시 상태를 확인하고 위치를 다시 연결할 수 있다.
11. Codex 요청이 실패하거나 취소되어도 기존 해설과 질문 초안을 유지한다.
12. 질문 이력과 새 응답이 코드·해설의 읽던 위치를 임의로 바꾸지 않는다.

## 14. 첫 구현의 구체화

- Windows에서 `start.cmd`로 실행하는 로컬 앱으로 구현한다. 기본 주소는 `http://127.0.0.1:4317`이다.
- UI는 React, 로컬 백엔드는 Node.js로 구성한다. 엔진 소스는 읽기 전용이며, 해설과 세션은 `%LOCALAPPDATA%\UEReader`에 원자적으로 저장한다.
- Codex 연결은 세션 유지 OFF에서 로컬 CLI 비대화형 실행, ON에서 App Server의 영구 스레드를 사용한다. 구조화된 JSON 응답과 기존 로그인을 이용하고 훅·플러그인·셸 도구를 끈다. 엔진 원본 대신 검증한 코드 발췌를 전달한다.
- 질문에 명시적으로 첨부한 범위를 보여준다. 질문과 해설 모두 작업공간 전용 읽기 도구로 필요한 구현을 조사할 수 있다. 고정된 관련 파일 3개·첫 200줄 자동 첨부는 사용하지 않는다. 확인한 구간은 완료된 요청의 `확인한 코드` 목록에서 볼 수 있다.
- 파일 개요 요청은 처음 1,200줄을 시작 자료로 제공하고 필요한 후속 구간은 에이전트가 읽는다. 실제로 확인한 범위를 넘어 전체 파일을 조사했다고 표현하지 않는다.
- 코드 검색은 한 번에 최대 100개 결과, 20초로 제한한다. 실제 검색한 파일 수와 부분 검색 여부를 표시한다.
- 코드 위치는 파일 내용 식별값과 정확한 원문 구간으로 확인한다. 원문이 여러 곳에 있거나 바뀌면 자동 연결을 중지한다. 사용자가 새 범위를 지정하여 다시 연결할 수 있다.
- CLI가 전달한 중간 메시지는 부분 응답으로 표시한다. 토큰별 스트리밍은 연결 인터페이스가 제공하는 범위에 따른다.
- 동작 확인용으로 직접 작성한 액터 예제를 제공한다. 실제 엔진 소스와 구분하며, 예제 해설도 명시한다.
- 응답 모델은 설정에서 선택하며 앱 전체에 저장한다. 모델 목록은 로컬 Codex의 `model/list`에서 동적으로 조회한다. CLI 버전 변경과 목록 새로고침을 지원한다. 조회 실패 시 마지막 목록을 사용하며, 선택 모델이 사라지면 알림과 함께 Codex 기본값으로 요청한다. 진행 중인 요청과 기존 답변 기록의 모델은 바꾸지 않는다.


## 15. 대화 세션과 오른쪽 화면 개선

- 설정에서 Codex 세션 유지를 켜거나 끈다. ON은 작업공간별 스레드를 재사용하고 앱 재시작 후 재개한다. OFF는 완료된 이전 대화를 0~50건 중 지정한 개수만 전달한다. 기본은 OFF·6건이다.
- ON에서는 질문 영역에 세션 새로고침을 표시한다. 저장된 답변을 삭제하지 않고 다음 질문부터 새 세션으로 시작한다.
- 오른쪽은 코드 해설 탭과 질문과 답변 탭으로 구성한다. 질문 입력창은 탭 아래에 고정하고 상단 경계를 드래그하여 높이를 조절한다. 높이는 작업공간별로 복원한다.
- 질문 전송 시 질문과 답변 탭을 표시한다. 공개 중간 메시지, 검색·파일 읽기 상태, 작성 중인 답변과 완료 결과를 순서대로 표시한다. 사용자가 이전 기록을 읽는 동안 자동으로 아래로 이동시키지 않는다.
- Codex 사용량 API가 제공하는 남은 비율과 초기화 시간을 질문 영역에 표시한다. 여러 그룹을 지원하고 조회 실패·미제공 상태를 구분한다.

## 16. 답변과 코드 해설 분리 및 탐색 개선

- 질문과 답변은 질문의 해결에 집중한다. 로컬 확인·일반 지식 같은 고정 분류를 답변이나 해설에 기계적으로 조립하지 않는다.
- 답변의 코드 해설 생성 버튼으로 별도 분석을 요청한다. 사용자가 대상 파일을 고르거나 에이전트가 관련 파일을 찾는다. 이전 답변은 배경으로 사용하고 현재 소스를 다시 확인한다.
- 해설은 실제 코드 구간별로 조건, 변수, 호출 순서, 상태 변화를 구체적으로 설명한다. 읽기 쉬운 문단과 필요한 목록을 사용하고 원문 구간을 펼쳐 볼 수 있게 한다.
- 답변에서 생성한 해설로 이동하고, 해설에서 원래 답변으로 돌아갈 수 있다. 해설의 이 구간 질문은 코드 범위를 질문에 넣고 입력창으로 이동한다.
- 탐색기의 펼침·접힘 상태는 검색과 목록 갱신, 재실행 후에도 유지한다. 파일을 열면 상위 폴더를 펼치고 해당 파일을 강조한다. 현재 파일 위치 표시와 모두 접기를 제공한다.
- 여러 파일을 비교하는 동안 질문 초안을 유지한다. 같은 이름의 헤더·구현 파일을 빠르게 전환한다. 후보가 여러 개면 검색으로 선택한다.
- 일반 질문, 파일 지정 없는 조사, 여러 파일 분석, 답변에서 해설 생성, 원래 대화로 복귀, 파일 변경 후 재분석을 검증한다. 동시에 중복 요청이 들어오면 하나만 실행한다.


## 17. 데스크톱 통합 및 문장별 소스 연결

- 화면과 로컬 백엔드를 Electron 기반 Windows 앱 하나에서 실행한다. 바탕화면에는 UE Reader 실행 바로가기만 제공한다. 창을 닫으면 초안을 저장하고 내장 서버와 세션 연결을 종료한다.
- 해설은 함수별로 나눈다. 세부 설명 문장마다 실제 코드의 좁은 라인 범위를 저장하고 마우스 또는 키보드 포커스로 강조한다. 소스 위치가 이동하면 문장 범위도 함께 이동하고, 내용이 달라지면 연결을 중지한다.
- 같은 파일 버전에서 인접하거나 겹치는 읽기 범위를 합쳐서 위치를 확인한다. 미확인 구간은 포함하지 않는다. 일부 해설의 위치가 잘못되면 해당 해설만 제외하고 구체적인 이유를 보여준다.
- 설정에 지침 프롬프트를 제공한다. 말투와 설명 방식 등을 지정하며, 저장한 지침은 기존 세션을 포함한 다음 요청부터 적용한다.


## 18. 함수 개요와 깊이 있는 세부 분석

- 각 함수의 역할, 입력·상태, 전체 동작 원리, 결과를 먼저 개요로 설명한다. 개요에 마우스 또는 키보드 포커스를 주면 분석 코드의 시작 라인 하나만 강조한다.
- 이후 중요한 분기, 상태 전이, 자료 구조, 호출 순서를 세부 항목으로 분석한다. 각 항목은 제목과 여러 문장·문단을 사용해 처리 과정과 이유, 결과를 설명한다. 중요하지 않은 라인을 기계적으로 나열하지 않는다.
- 세부 항목은 해당하는 좁은 코드 범위를 강조한다. 이전 해설은 다시 생성하면 새로운 구조를 사용할 수 있다.
- 설정 창을 넓히고 화면·해설 글꼴, 코드 글꼴, 앱 글자 크기, 해설·답변 글자 크기를 선택하거나 직접 입력해 미리 볼 수 있게 한다. 글꼴 설정은 모든 작업공간에 적용하고 저장한다.


## 19. 대규모 소스 탐색과 읽기 위치

- 전체 파일 경로를 인덱싱하고 탐색기는 보이는 행 주변만 가상 렌더링한다. 파일 더 보기 단계는 제거한다. 현재 파일의 앞뒤 파일을 즉시 확인할 수 있게 자동 이동한다.
- 폴더 순회는 제한된 병렬 작업으로 실행한다. 검색·정렬 및 C++ 구문 강조는 Web Worker에서 처리하여 화면 입력을 막지 않는다.
- 코드와 해설의 연결 이동은 상단에 작은 여백을 남긴다. 마지막 항목에도 같은 정렬을 적용한다.
- 앱 글자 크기는 탐색기·탭·설정에 적용하며 코드 및 해설·답변 크기와 독립적으로 저장한다.
- 밝은 화면과 어두운 화면의 구문 강조 대비를 높이고 여러 줄 주석·문자열의 분석 상태를 유지한다.


## 20. 영역 조절과 해설 직접 편집

- 탐색기 오른쪽 경계를 드래그하여 너비를 조절하고 작업공간별로 저장한다. 두 번 클릭하면 기본 너비로 돌아간다.
- 질문용 파란 라인 선택은 코드 본문의 드래그 또는 줄 번호의 클릭·드래그로 변경한다. 선택된 라인을 재클릭하거나 질문창의 첨부 제거로 해제한다. 해제 후 화면 코드를 대신 첨부하지 않는다. 줄 번호 드래그에서는 화면 끝의 자동 스크롤로 선택을 이어 간다.
- 코드에서 지정한 범위에 연결된 개요·세부 항목을 해설 영역에서 강조한다. 소스 내용이 달라졌거나 없는 해설은 자동 연결하지 않는다.
- 해설의 개요·세부 항목·기존 본문마다 우측 하단에 편집 버튼을 제공한다. 수정한 Markdown을 저장·취소할 수 있고 기존 소스 연결을 보존한다. 동시에 변경된 내용을 덮어쓰지 않으며 저장 실패 시 입력을 유지한다.

## 21. 질문 중심 분석과 상호작용 시각화

### 21.1 질문과 선택 코드

- 일반 질문은 현재 화면과 독립적으로 해석한다. 사용자 선택 코드, 대화 이력, 에이전트가 조사한 코드를 구분한다.
- `현재 코드 해설`, `파일 개요 생성`, `이 구간 질문`처럼 대상을 지정하는 동작은 해당 범위를 사용한다.
- 질문창에는 선택 코드가 없다는 상태를 표시한다. 제거한 코드가 다시 기본 첨부로 나타나면 안 된다.
- 기존 대화의 파일과 라인은 후속 질문을 이해하는 배경이다. 새 질문의 조사 범위를 제한하지 않는다.

### 21.2 시각화와 단계별 해설

- 주요 호출 흐름, 라이프사이클, 분기 또는 데이터 전달을 설명할 때 본문과 함께 시각화를 제공한다. 단순 질문에는 시각화를 강제하지 않는다.
- 직접 호출, 상태 전이, 조건 분기, 데이터 전달을 구분한다. 파일 읽기 순서를 실제 호출 관계로 표현하지 않는다.
- 단계를 클릭하면 해당 단계의 역할, 동작 이유, 상태 변화에 대한 해설을 바로 표시한다. 클릭만으로 새 LLM 요청을 보내지 않는다.
- 단계의 코드 링크를 클릭하면 저장된 소스 상태를 검증한 후 왼쪽에서 해당 범위를 연다. 개념 단계나 코드 미확인 단계에는 가짜 위치를 붙이지 않는다.
- 확대·축소, 키보드 선택, 전체 관계 목록을 제공한다. 긴 흐름도는 자체 스크롤 영역에서 읽는다.
- 시각화와 단계별 해설을 답변·코드 해설과 함께 저장한다. 다시 열 때 재생성이 필요하지 않다.
- 기존 답변에는 `흐름 시각화`를 제공한다. 원래 질문과 답변을 참고해 현재 소스를 조사하며, 열려 있는 화면 코드는 첨부하지 않는다.

### 21.3 프롬프트 원칙

- 사용자 질문의 의도와 필요한 설명 깊이를 우선한다.
- 관련 호출·선언·상태 전이를 찾아볼 수 있게 하며 제공된 발췌에 분석을 가두지 않는다.
- 문단 수와 고정된 근거 분류를 강요하지 않는다. 개념 설명과 실제 구현 근거를 자연스럽게 연결한다.
- 읽기 전용 접근, 허용된 소스 경로, 코드 위치 검증은 유지한다.
- 코드 해설의 표시 형식과 시각화 데이터 구조는 UI에 필요한 범위로 한정한다.
- 이전 형식에서 별도 저장된 상세 해설도 후속 질문에 활용하고 화면에서 다시 열어볼 수 있게 한다.
- 완료 기록에 프롬프트 버전과 실제 첨부 범위를 저장해 이후 품질 분석에서 사용한다.

### 21.4 추가 완료 기준

1. 파일을 열고 스크롤해도 선택하지 않은 코드는 일반 질문에 전달되지 않는다.
2. 코드 본문을 드래그한 범위가 질문창에 표시되고 전송되며, 제거 후 빈 선택을 유지한다.
3. 질문과 일반 해설 모두 필요한 추가 소스를 읽을 수 있다.
4. 시각화의 단계 선택으로 설명을 확인하고, 검증된 링크로 원본 위치를 열 수 있다.
5. 소스가 바뀌어 위치가 불명확하면 이동을 막고 이유를 표시한다. 설명은 유지한다.
6. 시각화가 저장·복원되고, 과거 답변에서도 새 시각화를 생성할 수 있다.
7. 노드의 일부 코드 연결이 잘못되어도 유효한 답변 전체를 폐기하지 않는다.

실제 기록 분석, 원인 구분과 구현 범위는 [분석 및 개선 기록](분석-개선-2026-10-09.md)에 정리한다.
