# UE Reader 사용 가이드

[README](../README.md)에서 다루지 않는 화면 동작, 에이전트 연결 방식, 저장 규칙과 처리 한도를 자세히 설명합니다. 코드 구조는 [`CODE_INDEX.md`](CODE_INDEX.md)를 보세요.

## 사용

- 탐색기는 전체 소스 파일 경로를 인덱싱하고 현재 화면 주변의 행만 표시합니다. **파일 더 보기** 없이 열린 파일과 주변 파일을 바로 탐색합니다. 검색·정렬과 C++ 구문 분석은 별도 작업에서 처리합니다.
- 스크롤 연결과 해설 항목 강조는 화면 상단에서 약간 떨어진 위치에 대상을 맞춥니다. C++ 강조는 여러 줄 주석·문자열을 유지하고 형식·함수·매크로를 구분합니다.
- 탐색기 또는 **Ctrl+P**에서 파일·심볼·코드 내용을 찾습니다. 코드 내용 검색은 2글자 이상부터 가능합니다.
- 탐색기 오른쪽 경계를 좌우로 드래그해 너비를 조절합니다. 너비는 작업공간별로 저장하며 경계를 두 번 클릭하면 기본값으로 복원합니다.
- 함수 개요와 세부 해설의 오른쪽 아래 **편집**에서 내용을 직접 수정합니다. Markdown, 저장·취소를 지원하며 원본 소스와 라인 연결은 유지합니다.
- 탐색기 폴더는 기본적으로 접혀 있습니다. 펼침·접힘 상태는 검색, 목록 갱신, 앱 재시작 후에도 유지합니다. 파일을 열면 해당 폴더를 펼치고 파일을 강조합니다. **현재 파일 위치 표시**, **모두 접기**도 제공합니다.
- 파일을 열지 않아도 **에이전트에게 질문**에서 질문할 수 있습니다. 에이전트는 지식·웹 검색·작업공간 검색으로 필요한 파일을 선택하고 읽습니다. 파일 없이 시작한 질문에서는 첫 추천 파일을 자동으로 엽니다. 조사 중 사용자가 다른 파일을 열거나 질문을 수정하면 자동 이동하지 않습니다.
- 소스 폴더 없이도 일반 질문을 할 수 있습니다. 상단 작업공간 메뉴의 **일반 질문 열기**로 해당 대화를 다시 열 수 있습니다.
- **줄 번호** 클릭·드래그로 질문에 첨부할 범위를 선택합니다. 코드 본문 드래그는 일반 텍스트 선택(복사용)이며 라인을 첨부하지 않지만, 선택한 줄에 연결된 해설 블록은 강조하고 그 위치로 스크롤합니다.
- 코드 본문을 **우클릭**하면 IDE처럼 **정의로 이동**, **선언으로 이동**, **모든 참조 검색**, **심볼 검색에서 보기**, **이 심볼에 대해 질문하기**, 선택 텍스트 복사를 사용할 수 있습니다. `Owner::Name` 형태는 소유 타입을 우선합니다. 변수는 먼저 현재 함수의 매개변수·지역 변수를 찾고(`obj->Name`, `obj.Name` 멤버 접근은 제외), 다음으로 현재 메서드가 속한 클래스의 멤버, 가까운 네임스페이스 순서로 인덱스에서 찾습니다. 후보가 여러 개면 심볼 검색 목록에서 고릅니다. 이동한 줄은 잠깐 깜빡여 위치를 알려 줍니다(검색 결과로 이동할 때도 같음). **Ctrl+T**로 타입·함수·매크로 심볼을 바로 검색합니다.
- **코드 인덱스**: 작업공간을 열면 백그라운드에서 C++ 심볼(클래스·구조체·열거형·함수 정의/선언·멤버/전역/static 변수·열거자·매크로·델리게이트·별칭, 네임스페이스와 클래스 범위 포함)과 검색 토큰 인덱스를 만들어 앱 데이터에 저장합니다. 다음 실행에서는 저장한 인덱스를 바로 쓰고 바뀐 파일만 다시 분석합니다(UE 5.6 엔진 소스 기준 최초 약 1분, 이후 약 10초). 코드 내용 검색은 인덱스로 후보 파일을 좁혀 빨라집니다. 진행 상황은 상태 표시줄에 나오며, 클릭하면 바뀐 파일을 다시 인덱싱합니다.
- 앱 시작 시 서버 연결 → 작업공간·설정 불러오기 단계를 로딩 화면으로 보여 주고, 실패하면 단계와 다시 시도 버튼을 표시합니다. 코드 인덱스를 처음 만드는 동안에는 진행률과 함께 지금 가능한 작업을 안내합니다. 화면 오류가 나도 빈 화면 대신 복구 안내를 표시합니다.
- 답변·해설의 Markdown 표, 취소선, 체크리스트를 표시합니다. 질문을 보내면 입력창을 비웁니다. Shift 클릭으로 확장하고, 선택된 라인 재클릭 또는 질문창의 제거 버튼으로 해제합니다. 일반 질문에는 선택한 코드만 첨부하며 현재 화면 코드는 자동 첨부하지 않습니다. 선택은 분석의 시작점이며 다른 구현도 탐색할 수 있습니다.
- 질문창의 **파일 첨부**(클립 버튼) 또는 끌어다 놓기로 작업공간 밖의 PDF·텍스트 파일(기획서, 메모 등)도 질문에 첨부할 수 있습니다. 앱이 텍스트를 추출해 질문과 함께 보내며(파일당 40MB, 요청당 150,000자까지, 넘으면 앞부분만 전달), 첨부는 선택한 코드처럼 제거할 때까지 유지되고 앱을 다시 시작하면 사라집니다. 스캔 이미지만 있는 PDF는 읽을 수 없습니다.
- 채팅에서 "인벤토리 시스템 코드 해설 만들어 줘"처럼 **해설 작성을 요청**하면, 에이전트가 관련 파일(보통 1–5개)을 직접 골라 읽고 구간별 해설을 만들어 저장합니다. 답변에는 고른 파일과 읽는 순서가 나오고, 답변 아래 **생성한 코드 해설** 링크와 해설 카드의 **원래 질문·답변** 링크로 서로 이동할 수 있습니다. 완료되면 첫 해설을 바로 엽니다(그사이 새 질문을 입력 중이면 알림만 표시). 일반 질문에는 해설을 만들지 않습니다.
- 질문창의 모델 이름 옆 **확장된 사고**를 켜면 다음 요청부터 세 단계로 처리합니다. ① 별도의 탐색 에이전트가 호출 관계·선언·대체 경로·스레드/수명 규칙까지 평소보다 넓게(도구 160회·600,000자) 조사합니다. ② 본 에이전트가 그 조사 결과로 답변이나 해설 초안을 씁니다. ③ 해설이면 검토 에이전트가 초안을 소스와 대조해 빠진 이유·용어 소개·중요한 블록을 보충하고 문장을 다듬습니다. 조사 결과는 답변 아래 **탐색 에이전트 조사 결과**에서, 검토 내용은 해설 진행 표시에서 볼 수 있습니다. 요청 시간과 사용량이 늘어나며, 탐색이나 검토가 실패하면 경고를 남기고 일반 결과를 저장합니다. 해설 다듬기에는 적용하지 않습니다.
- 작업공간 폴더 안의 문서(PDF, Markdown, 텍스트, CSV·JSON·INI·YAML, `.uproject`·`.uplugin`)는 에이전트가 직접 찾아 읽습니다. 문서는 참고 자료로만 쓰이며 코드 근거·해설 위치로 저장되지 않습니다.
- **파일 개요 생성**, **현재 코드 해설**, **질문 보내기**가 에이전트 요청을 시작합니다. 스크롤만으로는 요청하지 않습니다.
- 질문에는 질문에 맞는 답변을 제공합니다. 답변 아래의 **코드 해설 생성**에서 파일을 선택하거나 관련 파일을 자동으로 찾게 할 수 있습니다. 이 요청은 소스를 다시 읽어 별도 해설을 생성합니다.
- **흐름 시각화**로 기존 답변의 호출 흐름·라이프사이클을 요청할 수 있습니다. 새 답변과 해설에서도 관계 설명에 도움이 되면 시각화를 제공합니다. 단계를 클릭하면 설명이 표시되고, 코드 링크를 누르면 현재 소스의 대응 위치를 확인한 뒤 엽니다. 시각화는 자동 저장되며 확대·축소, 키보드 선택, 전체 관계 목록을 지원합니다.
- 이전 형식의 답변은 **기존 상세 해설**에서 펼쳐 읽을 수 있고 후속 분석에도 사용합니다. 답변의 상대 경로 소스 링크도 원본 위치로 연결됩니다.
- 해설은 유능한 강사처럼 목적과 맥락 → 핵심 개념(멘탈 모델) → 흐름 → 이유·주의점 순으로 설명합니다. 함수 단위 구간은 원본 라인 순서가 아니라 **이해하기 좋은 해설 순서**(보통 진입점·핵심 함수 → 의존하는 함수 → 보조 함수)로 표시하며, 파일 개요가 권장 읽기 순서를 안내합니다. 한 구간만 다시 생성하면 기존 위치를 유지하고, 파일 개요를 다시 만들면 새 해설 순서를 따릅니다.
- 개발 용어는 직역하지 않고 원문 용어나 일반적인 한글 표기를 사용합니다(예: GC, 리플렉션, 델리게이트, CDO).
- 해설은 함수 단위로 나누고 먼저 역할·동작 원리를 설명하는 함수 개요를 제공합니다. 개요에 마우스를 올리거나 키보드 포커스를 주면 함수 전체 범위를 강조합니다. 이후 중요한 분기·상태 변화·알고리즘을 세부 항목으로 깊게 분석하고 해당 소스 범위에 연결합니다. 단순 대입이나 로그 등 중요하지 않은 라인은 생략합니다. 문장에 마우스를 올리거나 키보드로 포커스하면 왼쪽 코드에서 해당 범위만 강조합니다. 기존 해설은 다시 생성하면 문장별 연결을 사용할 수 있습니다. 각 구간에서 참고한 코드 원문을 펼쳐 볼 수 있습니다. **이 구간 질문**, **원래 질문·답변**, 답변의 생성된 해설 링크로 두 탭을 오갑니다.
- 소스 도구 모음의 **헤더·구현 파일 전환**으로 같은 이름의 파일을 엽니다. 후보가 여러 개면 검색으로 선택합니다. 파일을 바꾸어도 작성 중인 질문은 유지됩니다.
- **ON/OFF** 버튼은 코드 범위와 해설 사이의 양방향 스크롤 연결을 제어합니다.
- 해설의 근거 링크로 관련 파일을 열고 **Alt+←/→**로 이동 기록을 탐색합니다.
- **저장한 해설**은 먼저 해설이 있는 파일 목록을 보여 주고, 파일을 고르면 그 파일의 해설 목록(해설 순서)을 엽니다. 제목·본문·파일 경로로 검색하고, 이름 변경·삭제·삭제 취소를 할 수 있습니다.
- **해설 다듬기**(코드 해설 도구 모음 또는 저장한 해설 창): 여러 파일을 골라 “어떻게 다듬을지” 요청을 적으면, 에이전트가 현재 소스를 다시 읽고 해설을 고쳐 씁니다. **필요하면 해설 추가**, **불필요한 해설 삭제**를 켜면 그 범위 안에서 에이전트가 스스로 판단해 추가·삭제·순서 변경을 합니다. 수정한 해설은 새 버전으로 저장되고(이전 버전 유지), 삭제는 완료 알림의 **되돌리기**로 복구할 수 있습니다. 한 번에 최대 10개 파일.
- 넓어진 설정 창의 **글꼴**에서 화면·해설 글꼴, 코드 글꼴, 앱 글자 크기, 해설·답변 글자 크기를 지정하고 미리보기 후 적용합니다. 설치된 글꼴 이름을 직접 입력할 수 있으며 모든 작업공간에 저장됩니다. 테마, 코드 글자 크기, 줄바꿈과 해설 길이도 조절할 수 있습니다.
- **설정 → AI 에이전트와 모델**(설정 창 맨 위)에서 Codex 또는 Claude Code를 고르고, 그 에이전트의 **응답 모델**을 선택합니다. 모델 목록은 설치된 CLI가 로그인한 계정 기준으로 실행 중에 알려 주는 목록이며(Codex 예: GPT-6.1-Sol·GPT-6-Luna, Claude 예: Opus 5.5·Sonnet 5.5·Fable 5.1·Haiku 5.5와 고정 버전), 에이전트마다 선택을 따로 저장합니다. 질문창의 `에이전트 · 모델` 표시를 눌러도 설정을 열 수 있습니다. 다음 요청부터 적용되며, 같은 채팅 안에서 에이전트를 바꿀 수도 있습니다.
- **질문과 답변**은 채팅별로 저장합니다. 질문 탭 위쪽의 채팅 바에서 현재 채팅 제목, **채팅 목록**, **새 채팅**을 사용합니다. 채팅 제목은 첫 답변을 받을 때 에이전트가 질문 내용에 맞는 자연스러운 제목으로 정하며, 제목을 두 번 클릭하거나 연필 버튼으로 언제든 바꿀 수 있습니다. 사용자가 바꾼 제목은 이후 덮어쓰지 않습니다.
- 채팅 목록에서 항목을 **우클릭**(또는 Shift+F10)하면 **이름 편집**과 **삭제**가 나타납니다. 삭제는 알림의 **실행 취소**로 되돌릴 수 있습니다. 이전 대화는 같은 채팅 안에서만 다음 질문에 전달됩니다.
- 파일 탭: **휠 클릭**으로 닫기, 우클릭 메뉴(닫기 · 다른 탭 모두 닫기 · 왼쪽/오른쪽 탭 닫기 · 모든 탭 닫기 · 경로/파일 이름 복사 · 탐색기에서 보기 · 즐겨찾기), 드래그로 순서 변경, 탭 막대에서 휠로 가로 스크롤. **Ctrl+W** 현재 탭 닫기, **Ctrl+Shift+T** 닫은 탭 다시 열기, **Ctrl+Tab / Ctrl+PageUp·PageDown** 탭 전환.
- **작업공간 폴더**(탐색기 상단의 폴더+ 버튼): 한 작업공간에 여러 소스 폴더를 함께 열 수 있습니다. 예를 들어 엔진 소스(기본 폴더)에 내 프로젝트 폴더를 추가하면 탐색기에 `프로젝트이름/`으로 나타나고, 검색·코드 인덱스·정의 이동·에이전트 질문이 두 폴더를 함께 다룹니다. 프로젝트 코드를 물어보면 에이전트가 엔진 코드까지 따라가 읽습니다. 폴더를 제거해도 해설은 남고, 같은 이름으로 다시 추가하면 다시 연결됩니다.
- **에이전트가 스스로 정하는 검색 범위**: 에이전트는 검색하기 전에 볼 곳을 정합니다. 엔진 구조 지식과 `list_folders`(폴더별 소스 파일 수)로 가장 작은 후보 폴더를 고르고, `find_symbol`(코드 인덱스의 정의·선언 위치)과 `search_code`(인덱스로 좁힌 후보 파일만 읽음)를 그 범위 안에서 실행합니다. 찾지 못하면 상위 폴더 → 모듈·프로젝트 → 전체 순으로 넓힙니다. 진행 과정에 `심볼 찾기 · Tick · 범위 Runtime`처럼 고른 범위가 표시됩니다.
- **사용자 검색 범위**: 탐색기에서 폴더나 파일을 **우클릭 → 에이전트 검색 범위에 추가**(또는 **이 폴더만 검색 범위로 지정**)하면, 에이전트가 따로 범위를 고르지 않을 때 그 안에서 먼저 찾습니다. 지정한 범위는 질문 입력창 위 **검색 범위** 칩으로 보이고, 칩의 ×나 **전체로**로 해제합니다. 범위 밖의 정의가 꼭 필요하면 에이전트가 전체에서 찾으며, 파일 읽기는 제한하지 않습니다. 작업공간별로 저장됩니다.
- **설정 → 에이전트 역할**: 지시문 맨 앞에 들어가는 **답변·해설 역할**과 **탐색 에이전트 역할**을 직접 고칠 수 있습니다. 기본 역할은 엔진 내부와 그 위의 게임 프로젝트를 함께 아는 시니어 프로그래머의 관점으로, 엔진 코드는 메커니즘과 설계를, 프로젝트·플러그인 코드는 게임 기능과 그 기반이 되는 엔진 프레임워크를 중심으로 설명합니다. 비우거나 **기본 역할로 복원**하면 기본값을 씁니다. 유지 중인 Codex 세션은 세션을 새로 시작한 뒤 적용됩니다.
- 질문 초안, 코드 선택, 파일 탭, 읽던 위치, 연결 상태는 작업공간별로 자동 저장합니다.
- **설정 → 응답 지침 → 지침 프롬프트**에 말투·설명 수준·형식을 입력하고 **지침 저장**을 누릅니다. 최대 12,000자이며 모든 작업공간의 다음 질문·해설부터 적용됩니다. 유지 중인 세션에도 새 지침을 전달하며, **기본값으로 복원**으로 지울 수 있습니다.

예제는 직접 작성한 액터 코드입니다. Unreal Engine 원본 소스나 빌드 가능한 게임 프로젝트를 포함하지 않습니다. 예제 해설은 직접 작성한 해설로 표시합니다.

## 에이전트

모든 에이전트는 로컬 CLI와 이미 로그인된 계정을 사용합니다. 별도 API 키 입력은 필요하지 않습니다. 어떤 에이전트든 앱이 제공하는 읽기 전용 소스 도구(`list_folders`, `find_symbol`, `search_files`, `search_code`, `read_file`, 문서용 `search_documents`, `read_document`)와 웹 검색만 사용할 수 있고, 셸·파일 쓰기·플러그인은 사용할 수 없습니다. 요청은 앱 데이터 아래의 요청별 폴더에서 실행하며 원본 소스 폴더를 작업 디렉터리로 쓰지 않습니다.

| 에이전트 | 로그인 | 실행 방식 | 모델 | 남은 사용량 |
| --- | --- | --- | --- | --- |
| Codex | `codex login` | `codex exec --output-schema`, 세션 유지 시 App Server 스레드 | App Server의 `model/list`에서 조회 | 표시 |
| Claude Code | `claude` 실행 후 `/login` | `claude -p --output-format stream-json --json-schema`, 내장 도구는 `WebSearch`·`WebFetch`만, `--permission-mode dontAsk`, `--strict-mcp-config` | stream-json 제어 프로토콜의 `initialize` 응답에서 계정별 목록 조회(별칭·고정 버전) | 미지원 |

Claude Code는 JSON Schema로 응답 형식을 강제합니다. 모델 목록 조회는 대화 메시지를 보내지 않으므로 사용량을 쓰지 않습니다. 로그인이 만료되면 요청 오류로 로그인 방법을 안내합니다. 모델 목록은 설정을 열 때 조회하고 10분이 지나거나 CLI 버전이 바뀌면 갱신합니다. 조회에 실패하면 마지막 목록을 보여 주며, 목록이 없어도 각 에이전트의 기본 모델로 사용할 수 있습니다.

### Codex 세부

연결되지 않으면 터미널에서 `codex login`을 실행한 뒤 설정에서 연결을 다시 확인하세요.

세션 유지 OFF와 코드 해설 생성은 `codex exec --json --output-schema`를 사용합니다. 현재 설치 버전에서 지원하는 `--ignore-user-config`, `--ignore-rules`, `--ephemeral`과 읽기 전용 샌드박스를 적용합니다. 셸·앱·플러그인·브라우저·훅·하위 에이전트 도구를 비활성화합니다. 요청별 별도 폴더에서 실행하며, 원본 소스 폴더를 Codex 작업 디렉터리로 사용하지 않습니다. 인증은 기존 Codex 로그인에서 가져옵니다.

세션 유지 OFF에서는 선택한 코드(있을 때)와 설정한 개수의 최근 완료된 대화를 전달합니다. 기본은 6건이며 0~50건으로 설정할 수 있습니다. 0건이면 이전 대화를 전달하지 않습니다. 질문 모드의 Codex는 실시간 웹 검색과 전용 읽기 전용 MCP 도구(`list_folders`, `find_symbol`, `search_files`, `search_code`, `read_file`)를 사용할 수 있습니다. 검색할 폴더를 먼저 고르고, 심볼·파일 이름·코드 문자열을 찾은 뒤 필요한 라인 범위를 직접 선택합니다. MCP 도구는 지정한 소스 폴더만 읽으며 셸이나 쓰기 기능을 제공하지 않습니다.

답변에는 **에이전트가 선택한 파일**, 선택 이유, **웹 출처**를 표시합니다. **확인한 코드**에서 실제 전달·열람한 구간을 볼 수 있습니다. 필요한 근거와 불확실성은 답변 문맥 안에서 설명하며, 고정된 분류를 기계적으로 붙이지 않습니다. 확인하지 않은 파일·라인을 코드 해설이나 자동 열기 대상으로 등록하지 않습니다.

파일 개요·선택 구간 해설도 읽기 전용 소스 도구로 관련 선언과 호출 구현을 조사할 수 있습니다. 처음 제공한 발췌만으로 분석을 제한하지 않습니다. 프롬프트는 `server/analysis/prompts.mjs`에서 관리하며 고정된 문단 수를 강제하지 않습니다.

질문을 보내면 오른쪽의 **질문과 답변** 탭으로 전환합니다. 공개 중간 메시지, 소스 검색·읽기, 웹 검색 상태와 작성 중인 답변을 대화 흐름에 표시합니다. 완료 후에는 진행 과정을 접어서 다시 볼 수 있습니다. CLI 모드는 제공되는 이벤트 단위로, 세션 유지 모드는 App Server의 응답 델타 단위로 갱신합니다. 구조화된 JSON은 화면에 그대로 표시하지 않습니다. 취소·실패한 부분 응답은 완료된 해설로 등록하지 않습니다. 요청 제한 시간은 10분입니다.

공식 인터페이스: [Codex 비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode), [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), [웹 검색 설정](https://learn.chatgpt.com/docs/config-file/config-reference).

### 세션과 질문 영역

- **설정 → 대화 설정 → (에이전트) 세션 유지**를 켜면 **채팅마다** 에이전트 세션을 유지합니다. Codex는 App Server 프로세스와 스레드를, Claude Code는 채팅별 작업 폴더에서 `--session-id`/`--resume`을 사용합니다. 같은 채팅에서 다른 에이전트로 바꾸면 그 에이전트의 새 세션에 채팅의 이전 대화를 한 번 전달합니다. 기본값은 OFF입니다.
- 세션 유지 시 이전 메시지·도구 결과는 Codex 스레드가 관리합니다. 앱이 최근 대화를 중복으로 붙이지 않습니다. 앱 재시작 뒤에는 저장한 스레드를 `thread/resume`으로 복원합니다. 대화가 길어지면 Codex의 컨텍스트 관리에 따라 오래된 내용이 요약될 수 있습니다.
- 세션 유지 ON에서 질문 영역에 **세션 새로고침** 버튼이 나타납니다. 현재 채팅의 다음 질문은 새 세션에서 시작하며, 이미 저장한 답변과 해설은 그대로 남습니다. 실행 중에는 새로고침할 수 없습니다.
- 세션 모드를 바꾸면 기존 연결을 닫고 다음 질문부터 새 세션을 사용합니다. 소스 폴더를 다른 경로로 다시 연결해도 세션을 새로 시작합니다. 코드 해설 생성은 질문 세션과 별도입니다.
- 세션 식별자는 앱 데이터에, 대화 기록은 각 에이전트 CLI의 로컬 세션 저장소에 보관합니다. 채팅별 세션 작업 폴더는 앱 데이터의 `agent-sessions` 아래에 생성합니다. 이전 버전의 질문 기록은 처음 실행할 때 작업공간별 `이전 기록` 채팅 하나로 옮깁니다. 앱이 관리하는 읽기 전용 도구만 연결하고 셸·앱·플러그인·훅을 끕니다.
- **코드 해설 / 질문과 답변** 탭은 오른쪽에서 전환합니다. 질문 입력창은 두 탭 아래에 고정됩니다. 입력창 위쪽 경계를 위아래로 드래그하거나 경계에 포커스를 둔 뒤 방향키로 높이를 조절할 수 있습니다. 높이는 작업공간별로 저장합니다.
- 질문 영역의 **남은 사용량**은 Codex에서 `account/rateLimits/read`가 반환한 계정 전체 사용 한도입니다. 사용량 API가 없는 에이전트는 미지원으로 표시합니다. 앱 시작·요청 완료·화면을 보고 있는 동안 1분 간격으로 갱신하며 수동 새로고침도 제공합니다. 초기화 시간은 수치 위에 마우스를 올리면 표시합니다. 여러 사용량 그룹이 있으면 각각 표시합니다.
- 조회 실패 시 이전 값임을 표시합니다. API가 사용량을 제공하지 않는 로그인에서는 조회 불가를 안내하며, 알 수 없는 사용량을 0%로 표시하지 않습니다.

공식 인터페이스: [Codex App Server의 스레드·사용량 API](https://learn.chatgpt.com/docs/app-server).

### 모델 목록과 업데이트

- 설치된 Codex의 `app-server`에 `initialize`와 `model/list`를 요청해 목록을 조회합니다. Luna·Sol·Astra 같은 모델명이나 버전을 앱에 고정하지 않습니다. 페이지가 나뉘면 전체 페이지를 읽습니다.
- 목록과 마지막 조회 시각을 로컬에 보관합니다. 설정을 열 때 조회하며, 10분이 지나거나 Codex CLI 버전이 바뀌면 갱신합니다. **모델 목록 새로고침**으로 즉시 다시 조회할 수도 있습니다.
- 목록 조회 실패 시 마지막 정상 목록을 표시합니다. 저장된 목록도 없으면 **Codex 기본값**을 계속 사용할 수 있습니다.
- 선택한 모델이 새 목록에서 사라지면 선택값은 보존하고 해당 요청은 Codex 기본값으로 실행합니다. 전환 사유는 요청 상태와 답변 기록에 표시합니다.
- 목록은 Codex가 제공하는 카탈로그입니다. 실제 모델 실행은 로그인한 계정과 서버 정책에 따릅니다.
- 진행 중인 요청의 모델은 바뀌지 않습니다. 답변 기록에는 사용하도록 전달한 모델 ID를 저장합니다. **Codex 기본값**을 선택하면 모델 ID를 고정하지 않고 CLI의 기본 선택을 따릅니다.

공식 인터페이스: [Codex App Server의 model/list](https://learn.chatgpt.com/docs/app-server#list-models-modellist).

## 저장과 소스 보호

- 기본 앱 데이터: `%LOCALAPPDATA%\UEReader\reader.json`
- 상태와 분석 기록은 브라우저 저장소가 아닌 로컬 파일에 저장합니다. 임시 파일과 원자적 교체로 저장하며, 실패하면 기존 데이터를 유지합니다.
- 소스 읽기·검색은 지정한 폴더 안으로 제한합니다. 폴더 밖으로 향하는 심볼릭 링크·정션과 경로 이탈 요청을 거부합니다.
- 파일 내용과 코드 구간을 SHA-256 및 원문 발췌로 확인합니다. 동일 코드가 한 곳에만 있으면 새 라인으로 연결합니다. 변경·중복·누락으로 위치가 불확실하면 자동 동기화를 중지합니다.
- 변경된 해설은 계속 읽을 수 있습니다. 새 범위를 선택하고 **선택 라인에 다시 연결**하거나 해당 구간을 다시 분석하세요.
- 폴더가 이동했으면 설정의 **소스 폴더 다시 연결**을 사용합니다. 작업공간 식별자와 기존 기록을 유지합니다.
- 서버는 `127.0.0.1`에만 바인딩하며, 외부 Origin·Host 요청을 거부합니다.

## 처리 범위

- 파일: `.cpp`, `.h`, `.hpp`, `.cc`, `.c`, `.inl`, `.cs`, `.usf`, `.ush`. UTF-8·UTF-16 LE, 최대 12MB.
- 파일 목록은 비동기로 생성합니다. `Binaries`, `Intermediate`, `Saved`, `DerivedDataCache` 등은 제외합니다.
- 코드 검색은 최대 100개 결과 또는 20초까지 실행하고, 검색한 파일 수와 미완료 여부를 표시합니다. 전체 엔진의 호출 그래프 색인은 아닙니다.
- 코드는 보이는 라인 중심으로 가상 렌더링합니다. 줄바꿈 시 행 높이는 고정폭 글꼴 기준으로 계산합니다.
- 파일 개요는 처음 1,200줄을 시작 자료로 전달하고 필요한 나머지는 에이전트가 읽습니다. 선택 첨부는 최대 12개 범위·100,000자입니다.
- 문서 도구(`search_documents`, `read_document`)는 PDF 텍스트를 페이지 표시와 함께 추출하며, 요청당 누적 300,000자를 읽습니다. 문서는 탐색기에 표시하지 않습니다.
- 질문과 해설의 소스 도구는 요청당 최대 64회, 누적 200,000자를 읽습니다. 파일 읽기는 한 번에 400줄까지 가능합니다. 에이전트 코드 검색은 코드 인덱스로 고른 후보 파일만 읽고 50개 결과·20초 제한이며, 부분 검색 상태를 반환합니다.
- 동일 파일·동일 버전의 이어지는 읽기 범위는 합쳐서 검증합니다. 읽지 않은 빈 구간은 연결하지 않습니다. 일부 해설이 잘못된 위치를 반환하면 검증된 해설은 저장하고 제외된 파일·라인과 이유를 표시합니다.
- 재생성한 해설은 이전 버전을 보존합니다. 답변에서 별도 해설 생성을 요청할 수 있으며, 생성한 해설에는 원래 답변으로 돌아가는 연결을 저장합니다.

## 환경 변수

| 변수 | 용도 |
| --- | --- |
| `PORT` | 서버 포트. 기본 `4317` |
| `UE_READER_DATA` | 앱 데이터 폴더 |
| `CODEX_BIN` | Codex 실행 파일의 절대 경로. 미지정 시 자동 탐색 |

| `CLAUDE_BIN` | Claude Code 실행 파일 경로. 미지정 시 PATH와 npm 설치 위치에서 탐색 |
