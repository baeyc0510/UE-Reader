# 엔진 분석 경험 개선 기록 — 2026-10-09

## 분석 대상

`%LOCALAPPDATA%\UEReader\reader.json`의 질문·답변, 코드 발췌, 해설, 활동 기록을 읽었다. 파일 자체는 변경하지 않았다.

총 5개 요청 중 1개는 예제, 4개는 실제 엔진 작업공간의 기록이다. 엔진 기록은 완료 3건, 실패 1건이다. 저장된 기록에는 당시 전체 프롬프트와 선택 경로의 출처가 없으므로, 과거 응답의 경향과 현재 구현에서 확인한 원인을 구분한다.

109–152행이 사용자가 직접 선택한 범위였는지는 기록만으로 확정할 수 없다. 다만 44행 범위는 현재 화면 자동 첨부 크기와 일치하며, 사용자 보고와 함께 구현을 점검할 근거가 된다.

## 현재 구현에서 확인한 원인

1. `src/App.tsx`의 `contextsFor()`는 질문에도 보이는 라인 전후의 코드를 추가했다. 선택을 제거해도 같은 코드가 다시 기본 컨텍스트로 나타났다.
2. `server/generation.mjs`는 컨텍스트가 비어 있으면 지정된 파일의 첫 180행을 추가했다. UI만 수정해도 서버에서 자동 첨부가 되살아날 수 있었다.
3. 코드 본문 드래그는 해설 강조에만 반영되고 질문 첨부를 변경하지 않았다. 실제 사용자 조작과 컨텍스트 전달이 일치하지 않았다.
4. 일반 코드 해설에는 추가 도구 사용을 금지하고 제공된 발췌만 분석하도록 지시했다. 관련 파일도 최대 3개의 첫 200행만 붙여 필요한 구현을 놓칠 수 있었다.
5. 해설 지침에 고정된 문단 수와 상세 형식 요구가 많았다. 소스 위치 검증과 별개로 설명 방식까지 지나치게 지정하고 있었다.
6. 예전 형식의 상세 답변은 `sections`에 저장돼 있지만 후속 질문 이력에는 `answer` 요약만 포함됐다. 질문 화면도 그 상세 해설을 직접 보여주지 않았다.
7. 기존 Markdown 표시기는 `source:` 링크만 코드 이동으로 처리했다. 실제 기록에 있는 상대 경로 Markdown 링크는 클릭할 수 없었다.

현재 프롬프트는 이미 고정된 근거 분류를 금지하고 있었다. 따라서 과거 기록의 반복 분류를 현재 지침이 그대로 요구한다고 판단하지 않았다. 개선은 남아 있는 자동 첨부, 도구 제한, 과도한 형식 지정, 이력 손실에 집중했다.

## 구현한 기능

### 선택한 코드만 질문에 첨부

일반 질문에서는 현재 열린 파일 경로와 화면 코드를 보내지 않는다. 백엔드도 질문의 `path`를 읽거나 자동 발췌하지 않는다. 코드 드래그·라인 선택·명시적인 구간 질문으로 지정한 범위만 첨부한다. 첨부된 코드는 분석의 출발점이며 질문의 범위를 제한하지 않는다.

명시적으로 누른 `현재 코드 해설`과 `파일 개요 생성`은 해당 대상을 유지한다.

### 클릭 가능한 분석 시각화

답변과 해설 응답에 호출 흐름·라이프사이클·데이터 흐름 데이터를 받을 수 있게 했다. 각 단계는 설명과 선택적인 코드 근거를 가지며 화살표는 호출·전이·조건·데이터 관계를 구분한다.

단계를 누르면 설명을 바로 표시하고, 코드 링크는 클릭 시 현재 소스와 다시 대조한다. 동일 코드의 라인 이동은 따라가고 변경·중복으로 위치를 확정할 수 없으면 이동을 막는다. 불확실한 코드 링크 때문에 답변 전체를 버리지 않는다.

기존 답변의 `흐름 시각화` 버튼으로 원래 분석을 이어서 조사할 수 있다. 단계 설명, 관계, 코드 근거는 원래 응답과 함께 로컬에 저장한다.

### 분석 능력을 보존하는 프롬프트

일반 해설에도 읽기 전용 소스 도구를 제공한다. 필요한 호출자·피호출자·선언을 직접 찾아 읽을 수 있다. 설명 분량은 질문과 구현 복잡도에 맞추며, 확인하지 못한 사항은 해석에 영향을 주는 위치에서만 설명하도록 했다.

원본 수정 금지, 작업공간 제한, 검증된 라인 연결은 유지했다. 모델 선택이나 사용자의 지침 설정은 변경하지 않았다. 프롬프트는 `server/prompts.mjs`에서 관리하고 완료 기록에 버전을 남긴다.

과도한 작업 절차와 지침이 모델을 제한할 수 있다는 [OpenAI 공식 안내](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)를 참고했다. 해당 문서는 특정 모델을 다루므로 현재 선택된 모델의 품질 개선을 보장하는 근거로 쓰지 않았다. 실제 변경은 로컬 기록과 코드에서 확인한 문제에 근거한다.

### 분석 맥락과 탐색 복원

과거 상세 해설을 질문 화면에서 펼쳐 읽고 후속 질문에도 전달한다. 상대 경로의 소스 Markdown 링크를 지원한다. 경로 밖 접근 제한은 백엔드에서 계속 적용한다.

## 후속 개선 후보

- 큰 흐름의 단계별 확장: 한 번에 전체 그래프를 펼치지 않고 선택한 단계의 하위 호출만 추가 조사한다.
- 분기 비교 보기: 동일 함수의 조건별 경로를 나란히 보여준다.
- 역할 중심 탐색: 객체 소유권, 실행 스레드, 상태 변경자를 질문에 따라 묶어 표시한다.

이번 구현은 선택 컨텍스트, 시각화와 저장·코드 연결, 프롬프트, 기존 분석 기록 활용에 집중했다. 전체 엔진의 정적 호출 그래프를 생성하는 기능은 포함하지 않는다.
